# 完整赛季切换设计

## 目标

在单页静态站点中查看当前及历史赛季。切换赛季后，总览、财报、动态、荣誉、TOP 4、完整积分榜、玩家档案和全部战报统一切换，不新增历史页面。

## 数据来源

- 赛季列表由 `data/games.json` 中所有 `season` 值自动生成。
- `data/rules.json` 中的 `season.current` 始终作为默认赛季，并在选择器中标记为“当前赛季”。
- 其他赛季标记为“已结束”。
- 所有赛季均使用当前 `rules.json` 重新计算，不保存规则快照。

## 选择与 URL

- 页面标题右侧提供原生下拉选择器，移动端排到标题下方并占满可用宽度。
- 默认选择 URL 查询参数 `season` 指定的有效赛季；参数缺失或无效时回退到 `rules.season.current`。
- 切换后使用 `history.replaceState` 将 URL 更新为 `?season=<season-id>`，刷新和分享链接都能恢复同一赛季。

## 计算与渲染

- `calculateSeasonSummary()` 接受可选的 `selectedSeason` 参数，不再只能读取当前赛季。
- 初始化时数据只加载一次；切换赛季只重新计算并调用现有各区域渲染函数。
- 切换时战报页码和财报页码重置到所选赛季的最新一局。
- 玩家档案事件只注册一次，并从当前活动赛季摘要中读取资料，避免重复监听和跨赛季旧数据。

## 状态与文案

- 历史赛季总览标题显示具体赛季编号。
- 当前赛季继续使用“预计赛季奖励”；历史赛季显示“赛季奖励”。
- 没有有效牌局的赛季沿用现有空状态。

## 验证

- 赛季列表包含 S2 和 S1，当前赛季优先。
- 合法 URL 参数能选择历史赛季，非法参数回退当前赛季。
- S1 计算 4 局，S2 计算 1 局，积分与奖池互不串季。
- 切换后财报、战报和玩家档案使用同一选中赛季。
- 下拉选择器在桌面和移动端不溢出。
